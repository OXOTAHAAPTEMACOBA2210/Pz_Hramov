## 1. Цель работы
Изучение и практическое применение обобщенных представлений на основе классов (Generic Class-Based Views: ListView и DetailView) в проекте «Сайт университета», реализация списочных и детальных страниц для всех основных сущностей базы данных (Студенты, Преподаватели, Группы, Факультеты, Дисциплины), организация перекрестных связей, пагинации, поиска и подготовка ответов на контрольные вопросы.

## 2. Реализация архитектуры CBV
- Для моделей `Student`, `Teacher`, `Group`, `Faculty`, `Discipline` созданы пары `ListView` и `DetailView`.
- В `StudentListView` реализована сортировка `order_by('last_name', 'first_name')`, пагинация (`paginate_by = 5`) и поиск по фамилии через параметр `q`.
- В шаблонах используется сквозная нумерация строк `{{ page_obj.start_index|add:forloop.counter0 }}` и вывод «Фамилия Имя».
- Реализованы перекрестные ссылки между связанными моделями (группа -> студенты, дисциплина -> преподаватель).

## 3. Ответы на контрольные вопросы
**1. Для чего используется ListView?**

ListView предназначен для генерации страниц со списками объектов из базы данных. Он инкапсулирует логику обращения к ORM, фильтрацию, сортировку, пагинацию (постраничный вывод) и передачу набора объектов в шаблон под заданным именем.

**2. Для чего используется DetailView?**

DetailView предназначен для детального отображения одного конкретного объекта модели. Он извлекает идентификатор (pk) из URL, находит запись в таблице базы данных и передает объект в шаблон, возвращая 404 ошибку при отсутствии объекта.

**3. Чем ListView отличается от DetailView?**

ListView оперирует множеством записей (QuerySet) и формирует списочные представления с поддержкой пагинации. DetailView оперирует ровно одним экземпляром модели по его первичному ключу.

**4. Что определяет атрибут model?**

Атрибут model связывает представление с соответствующим классом модели Django, определяя источник данных (Model.objects.all()) и базовые параметры контекста.

**5. Для чего используется template_name?**

template_name явно указывает относительный путь к файлу HTML-шаблона, используемому для рендеринга страницы, позволяя размещать шаблоны в нужных каталогах приложения.

**6. Для чего используется context_object_name?**

context_object_name задает читаемое имя переменной в шаблоне (например, 'students' вместо стандартного 'object_list').

**7. Зачем используется as_view()?**

Метод as_view() преобразует класс представления (CBV) в вызываемую функцию представления (FBV), которую ожидает диспетчер URL Django.

**8. Что означает <int:pk> в маршруте?**

Это конвертер пути URL, требующий наличия положительного целого числа, которое передается в представление в качестве именованного аргумента pk (primary key).

**9. Как DetailView определяет, какой объект нужно вывести?**

DetailView считывает аргумент pk из параметров маршрута и выполняет запрос к базе данных вида model.objects.filter(pk=pk).first().

**10. Что произойдёт при переходе к несуществующему pk?**

Метод get_object() вызовет исключение Http404, и Django отдаст клиенту стандартный ответ 404 Not Found без падения сервера.

**11. Для чего используется get_queryset()?**

Метод get_queryset() переопределяется для задания динамической сортировки, поиска по параметрам запроса, фильтрации и оптимизации связей через select_related и prefetch_related.

**12. Для чего в шаблоне нужен {% empty %}?**

Тег {% empty %} задает блок разметки, отображаемый внутри цикла {% for %} в случае, если переданный список объектов пуст.

**13. Почему лучше использовать {% url %}, а не записывать адрес ссылки вручную?**

Использование тега {% url %} обеспечивает слабую связанность (DRY): при изменении пути в urls.py ссылки во всех шаблонах обновятся автоматически.

**14. Почему список и подробную информацию целесообразно оформлять отдельными шаблонами?**

Списочный шаблон ориентирован на компактный табличный обзор множества строк с пагинацией, а детальный — на отображение полного состава атрибутов и связанных таблиц конкретного объекта. Разделение шаблонов упрощает код и его сопровождение.
