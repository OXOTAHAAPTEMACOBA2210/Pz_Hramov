## 1. Цель работы

## 3. Ответы на контрольные вопросы
**1. Чем ListView отличается от DetailView?**

ListView предназначен для работы с набором (списком) объектов модели из базы данных и возвращает коллекцию записей (QuerySet). DetailView предназначен для извлечения и отображения ровно одного конкретного объекта по его первичному ключу (pk или id) либо слагу (slug).

**2. Зачем у class-based view вызывается метод as_view()?**

Маршрутизатор URL Django рассчитан на вызов функций представления. Метод as_view() является фабричным методом класса, создающим функцию-обертку, которая принимает запрос HttpRequest, инициализирует экземпляр класса представления и направляет вызов соответствующему методу (get, post и др.).

**3. Что задаёт атрибут model?**

Атрибут model определяет, с какой моделью данных работает представление. На его основе автоматически формируется базовый запрос к базе данных (Model.objects.all()) и генерируются стандартные переменные контекста шаблона.

**4. Для чего используется template_name?**

Атрибут template_name явно определяет относительный путь к файлу HTML-шаблона, используемому для рендеринга ответа, позволяя переопределить стандартное имя шаблона по умолчанию.

**5. Что меняет context_object_name?**

Атрибут context_object_name задает пользовательское имя переменной в контексте шаблона вместо стандартного object_list (для ListView) или object (для DetailView), делая обращение к данным в шаблоне более наглядным.

**6. Откуда DetailView получает pk?**

DetailView считывает значение pk из словаря именованных аргументов маршрута URL (kwargs), которые парсятся из пути запроса в соответствии с маской <int:pk>.

**7. Что произойдёт, если объект с таким pk не существует?**

Метод get_object() вызовет исключение Http404, и Django вернет клиенту стандартную страницу с кодом ошибки 404 Not Found, не приводя к падению сервера.

**8. Зачем использовать именованные URL вместо жёстко записанных адресов?**

Использование именованных маршрутов (через тег {% url %} или функцию reverse()) обеспечивает слабую связанность: при изменении структуры адресов в urls.py все ссылки в шаблонах и редиректы обновляются автоматически.

**9. Для чего в шаблоне используется {% empty %}?**

Тег {% empty %} задает блок HTML-разметки, отображаемый в случае, если список в цикле {% for %} пуст или равен None, что исключает необходимость писать отдельное условие {% if %}.

**10. Чем {{ machine.status }} отличается от {{ machine.get_status_display }}?**

Выражение {{ machine.status }} возвращает сохраненный в базе данных технический код (например, 'W'), а {{ machine.get_status_display }} вызывает встроенный метод модели, возвращающий читаемый текст из перечисления choices ('Исправна').

**11. Какую задачу решают Bootstrap-классы row и col-*?**

Классы row и col-* реализуют 12-колоночную гибкую сетку на Flexbox, распределяя элементы по ширине и обеспечивая адаптивное перестроение карточек при изменении разрешения экрана.

**12. В каком случае имеет смысл переопределять get_queryset()?**

Переопределение get_queryset() необходимо для задания пользовательской сортировки, фильтрации по GET-параметрам, ограничения выборки текущим пользователем или оптимизации запросов к БД через select_related/prefetch_related.
